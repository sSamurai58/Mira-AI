# PRD

Продукт: **Mira** — голосовой ИИ-помощник.  
Источник правды по scope. Фича без строки здесь — не целевая (см. `RULES.md`).

## Цель

Говорить с Mira как с собеседником: живой диалог, человечная речь, память о прошлом, доступ к сети и экрану — с подключением современных ИИ-моделей (Claude, Gemini, GPT и др.).

Базовый контур: **слух → модель / диалог → действие (экран, браузер, сеть) → человечная речь**, состояние и история в SQLite.

## Обязательные возможности

Ниже — **must-have** продукта. Список будет расширяться; новые пункты добавлять сюда же с id и статусом в таблице «Есть vs stubs».

| # | Возможность | Суть |
|---|-------------|------|
| **1** | Полноценный диалог | Свободный разговор уровня ChatGPT: контекст, уточнения, длинные темы — не только команды «включи / выключи». |
| **2** | Человечная речь | Ответы звучат естественно: интонация, паузы, темп; не «робот-синтезатор». Качество TTS — критерий приёмки, не опция. |
| **3** | Память и обучение на разговорах | Все диалоги сохраняются и используются: Mira может ответить, *что было тогда-то* и *о чём мы говорили*. История ищется и поднимается в контекст. |
| **4** | Доступ в интернет | По запросу: актуальная информация, поиск, загрузка нужного из сети (через политики безопасности и `.env`). |
| **5** | Популярные ИИ API | Подключение агентов/моделей вроде **Claude**, **Gemini**, **GPT** (и смена провайдера без ломки продукта). Ключи только в `.env`. |
| **6** | Видимость экрана | Mira видит, что происходит на экране пользователя (скрин / поток), чтобы опираться на визуальный контекст в ответах. |
| **7** | Контроль экрана | По команде взаимодействует с тем, что видит: клики, ввод, навигация по UI — полный контроль рабочего стола в рамках разрешений пользователя. |
| **8** | Браузер | Полное взаимодействие с браузерами: открыть сайт, найти информацию, просмотреть историю, найти сайт «на котором я уже был» по критериям пользователя. |

## Пользовательские сценарии (ориентиры)

1. **Диалог:** «Объясни простыми словами…» → развёрнутый ответ голосом и текстом, с уточняющими вопросами.
2. **Память:** «О чём мы вчера говорили про отпуск?» → Mira находит прошлый разговор и резюмирует.
3. **Сеть:** «Что сейчас погоды в Москве?» → ответ с опорой на интернет.
4. **Экран:** «Что у меня открыто?» / «Нажми на кнопку сохранить» → видит экран и действует.
5. **Браузер:** «Найди сайт с рецептом, который я открывал на прошлой неделе» → история + критерии → открытие.

## Нефункциональные требования

- Секреты и API-ключи — только `.env`, не в git.
- Контроль экрана и браузера — **только по явной команде** пользователя; разрушительные действия — с подтверждением (детали в RULES/MEMORY).
- Провайдеры ИИ сменные; продукт не lock-in на одного вендора.
- История разговоров локальна (SQLite); удаление/очистка — обязательный UX позже.
- Человечность речи измеряем на слух при выборе TTS (зафиксировать выбор в MEMORY).

## Критерии готовности (обязательный набор)

Считаем обязательный scope закрытым, когда для пунктов **1–8** статус ≥ `partial` с рабочим happy-path, а для приёмки продукта — `done` по каждому:

1. Свободный диалог через выбранный LLM.  
2. Ответ озвучен «не роботом» (согласованный TTS).  
3. Вопрос про прошлый разговор находит историю.  
4. Запрос с опорой на интернет выполняется.  
5. Можно переключить Claude / Gemini / GPT (или эквивалент).  
6–7. Mira видит экран и выполняет простую UI-команду.  
8. Открытие сайта / поиск по истории браузера по критерию.
