# PRD

Продукт: **Mira** — локальный голосовой помощник.  
Источник правды по scope. Фича без строки здесь — не целевая (см. `RULES.md`).

## Цель

Один пользователь, одна машина: говорить с Mira голосом, получать голосовой ответ, выполнять понятные команды — **без обязательного облака**.

Контур: **слух (ASR) → понимание / диалог → действие → речь (TTS)**, состояние в SQLite.

Финансовый поток (депозит → счета → доля → вывод) — **доменный навык фазы 2**, не блокер голосового MVP.

## Возможности

### MVP (должен уметь)

| Возможность | Описание |
|-------------|----------|
| Слушать | Захват с микрофона, старт по кнопке / push-to-talk (wake-word — позже) |
| Распознавать речь | ASR, приоритет **русский**; текст уходит в диалог |
| Понимать простые команды | Интенты: приветствие, время/дата, справка, статус, стоп/отмена |
| Отвечать голосом | TTS озвучивает ответ ассистента |
| Короткий диалог | Контекст текущей сессии (несколько реплик), сброс по команде |
| Текст + голос | На экране видны распознанная фраза и ответ (для отладки и тишины) |
| Локальные данные | Сессии / история реплик в SQLite; секреты только в `.env` |
| Явные stubs | Нет «фейкового успеха» без реального ASR/TTS/действия |

### Рядом после MVP (планы)

| Возможность | Описание |
|-------------|----------|
| Wake-word / hands-free | Активация голосом без кнопки |
| Barge-in | Перебить ответ ассистента новой фразой |
| Память между сессиями | Факты о пользователе / предпочтения (имя, стиль ответа) |
| Навыки (skills) | Подключаемые действия: таймер, заметки, запуск локальных сценариев |
| Финансовый навык | Голосом: депозит, счета, доля, вывод + UI из DESIGN |
| Выбор движков | Смена ASR/TTS-бэкенда без переписывания диалога |
| Офлайн-профиль | Работа без сети, если выбранные движки это позволяют |

## Пользовательский сценарий (MVP)

1. Открыть Mira → состояние **готово**.
2. Зажать/нажать «говорить» → **слушаю** → произнести команду.
3. Увидеть распознанный текст → **думаю** → действие или ответ.
4. Услышать TTS и увидеть текст ответа → снова **готово**.
5. «Стоп» / отмена — прервать слушание или озвучку без порчи данных.

## Нефункциональные требования

- Локальный-first: MVP не требует облака (если движки локальные; облачные ASR/TTS — только явно и через `.env`).
- Один процесс; UI и пайплайн голоса вместе.
- Секреты не в git.
- Задержка ответа и качество RU — фиксировать целевые цифры в MEMORY при выборе движков.

## Критерии готовности MVP

1. Push-to-talk → ASR (RU) → ответ по одному из MVP-интентов → TTS.
2. Реплики пишутся в SQLite; переживают перезапуск.
3. На экране видны состояния и текст; stubs помечены.
4. Нет финансовых операций в MVP, пока навык не подключён (фаза 2).
