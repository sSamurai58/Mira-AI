# PRD

Продукт: **Mira** — голосовой ИИ-помощник.  
Источник правды по scope. Фича без строки здесь — не целевая (см. `RULES.md`).

## Цель

Говорить с Mira как с собеседником: живой диалог, человечная речь, память о прошлом, доступ к сети и экрану — с подключением современных ИИ-моделей (Claude, Gemini, GPT и др.).

Базовый контур: **слух → модель / диалог → действие (экран, браузер, сеть) → человечная речь**, состояние и история в SQLite.

## Обязательные возможности

Ниже — **must-have** продукта. Список будет расширяться; новые пункты добавлять сюда же с id и статусом в таблице «Есть vs stubs».

| # | Возможность | Суть |
|---|-------------|------|
| **1** | Полноценный диалог | Свободный разговор уровня ChatGPT: контекст, уточнения, длинные темы — не только команды «включи / выключи». |
| **2** | Человечная речь | Ответы звучат естественно: интонация, паузы, темп; не «робот-синтезатор». Качество TTS — критерий приёмки, не опция. |
| **3** | Память и обучение на разговорах | Все диалоги сохраняются и используются: Mira может ответить, *что было тогда-то* и *о чём мы говорили*. История ищется и поднимается в контекст. |
| **4** | Доступ в интернет | По запросу: актуальная информация, поиск, загрузка нужного из сети (через политики безопасности и `.env`). |
| **5** | Популярные ИИ API | Подключение агентов/моделей вроде **Claude**, **Gemini**, **GPT** (и смена провайдера без ломки продукта). Ключи только в `.env`. |
| **6** | Видимость экрана | Mira видит, что происходит на экране пользователя (скрин / поток), чтобы опираться на визуальный контекст в ответах. |
| **7** | Контроль экрана | По команде взаимодействует с тем, что видит: клики, ввод, навигация по UI — полный контроль рабочего стола в рамках разрешений пользователя. |
| **8** | Браузер | Полное взаимодействие с браузерами: открыть сайт, найти информацию, просмотреть историю, найти сайт «на котором я уже был» по критериям пользователя. |
| **9** | Скиллы | Каталог skills (как Cursor / Claude): **добавление** без пересборки ядра. Скиллы **по умолчанию неактивны** — Mira **подключает нужные по необходимости** (задача / команда пользователя), например skill для кода только когда надо писать код; «просто так» в контексте не висят. |
| **10** | Протоколы | Особые команды и **последовательности** команд/действий. Добавление: **md-файлами** (как skills) и через **Панель** в UI — список, создание, правки, запуск, вкл/выкл. |
| **11** | Голоса | **Выбор** голоса озвучки из каталога и **добавление новых** (импорт / подключение пакета голоса) без пересборки ядра. |
| **12** | Мессенджеры | По команде пользователя Mira **пишет и отвечает** разным людям в мессенджерах: Telegram, WhatsApp, Instagram и аналоги — отправка, ответы в диалогах, выбор получателя/чата. |
| **13** | Blender 3D | **Полноценный доступ и работа в Blender**: сцена, моделирование, материалы, анимация/рендер по задаче. При работе в Blender **on-demand включаются соответствующие skills** (как в #9); вне задач Blender эти skills неактивны. |
| **14** | Обучение по материалам | Загрузка литературы/медиа → глубокий разбор → план → извлечение знаний (фразы, стиль, логика) → память → при необходимости черновик skill. Конкретные задачи — ниже. |
| **15** | Студия голоса (встроенная) | Цикл: **Создать голос** → сгенерировать фразы → загрузить записи → **Mira сама обрабатывает** → при необходимости ещё фразы (расширение словаря/качества) → снова обработка. Итог — TTS в каталоге (#11), опц. LLM-профиль. Задачи и UX — ниже. |

### PRD #14 — конкретные задачи

Пользователь загружает материалы; Mira **учится** на них и **запоминает**. Разбивка на проверяемые задачи:

| ID | Задача | Результат |
|----|--------|-----------|
| **14.1** | Загрузка в библиотеку | Импорт **книг/текстов** (pdf, epub, txt, md…), **видео**, **аудио** в библиотеку Mira; метаданные (название, тип, дата) |
| **14.2** | Извлечение содержимого | Текст из документов; транскрипт/субтитры из аудио и видео (где возможно) |
| **14.3** | Глубокий анализ | Структура материала, тезисы, аргументы, термины, тон/стиль, устойчивые **выражения и фразы**, ходы **логики** / приёмы рассуждения |
| **14.4** | План освоения | Автоматический **план**: что выучить, в каком порядке, как применять в диалоге/действиях |
| **14.5** | Сохранение знаний | Запись извлечённого в долговременную память (связь с #3): факты, цитаты/фразы, паттерны логики, ссылка на источник |
| **14.6** | Применение в диалоге | По запросу («говори в стиле книги X», «вспомни логику из лекции Y») — подъём нужных фрагментов в контекст |
| **14.7** | Черновик skill | Если анализ показывает устойчивый навык — **предложить** skill (md) в каталог (#9); создание только после подтверждения пользователя; skill по умолчанию **неактивен** |
| **14.8** | Повторное обучение | Дозагрузка / обновление материала → инкрементальный разбор без потери предыдущей памяти (версии/слияние) |
| **14.9** | Обзор библиотеки | UI: список материалов, статус разбора (новый / в работе / готов), что выучено, связанные skills |

### PRD #15 — как работает (UX-цикл)

Грубый сценарий пользователя — **петля развития**, не разовый мастер:

1. **Создать новый голос** — кнопка в Студии → проект (имя, язык).
2. **Сгенерировать фразы** — Mira выдаёт пачку фраз для начитки; **не повторяет** уже сгенерированные и уже записанные.
3. Пользователь **записывает** их снаружи или в приложении и **загружает** записи в проект (или пишет прямо в сессии записи).
4. **Ассистент сам обрабатывает:** приём корпуса → анализ качества → сборка/обновление TTS (и при необходимости LLM-профиля) → статус «готово / нужно ещё данных».
5. **Развитие:** если качества/словаря мало — снова **сгенерировать ещё фразы** (новые, с дедупом) → записать/загрузить → снова автообработка.
6. Голос доступен в каталоге **#11**; цикл 2→5 можно крутить сколько угодно для роста словаря и естественности.

```
[Создать голос]
      ↓
[Сгенерировать фразы] ←──────────────┐
      ↓                               │
[Записать / загрузить]                │  ещё фразы
      ↓                               │  (словарь↑)
[Mira обрабатывает сама] ─────────────┘
  анализ → train/update TTS
      ↓
[Голос в каталоге #11 + превью]
```

### PRD #15 — конкретные задачи (студия голоса)

Встроенная функция продукта: пайплайн своего TTS (+ опц. LLM-профиль). Связь с **#11** и **#2**.

| ID | Задача | Результат |
|----|--------|-----------|
| **15.1** | Создать новый голос | Кнопка «Создать» → проект: имя, язык, статус цикла |
| **15.2** | Генерация фраз | Пачка фраз для начитки; **дедуп** vs уже сгенерированные и уже записанные; кнопка «ещё фраз» в том же проекте |
| **15.3** | Сессия записи (опц.) | Запись в приложении: фраза → mic → пара текст+аудио |
| **15.4** | Загрузка записанных | Импорт wav/flac (+ текст/имена файлов) после внешней начитки |
| **15.5** | Автообработка: анализ | После загрузки Mira **сама** гоняет QA: громкость, клиппинг, тишина, длина, матч тексту; отчёт |
| **15.6** | Автообработка: сборка TTS | Без ручных шагов пайплайна — train/update TTS из принятого корпуса |
| **15.7** | В каталог | Успешная сборка → голос в **#11** (или обновление существующего) |
| **15.8** | Цикл развития | Превью; рекомендация «добавь N фраз / закрой фонемы X»; повтор 15.2→15.6 для словаря и качества |
| **15.9** | LLM-профиль (опц.) | Параллельно или после TTS — профиль/дообучение LLM, привязанный к голосу (способ TBD) |

### PRD #16 — конкретные задачи (терминал)

Встроенный полноценный terminal emulator + shell-сессии. **Не** пятый корневой таб: **Мастерская → Терминал**; опционально split-панель из Диалога.

| ID | Задача | Результат |
|----|--------|-----------|
| **16.1** | Эмулятор терминала | Полноценный TTY-вид: шрифт mono, скролл, выделение/копирование, resize |
| **16.2** | Shell-сессия | Запуск login/interactive shell (OS-native); корректный cwd, env, exit-код |
| **16.3** | Интерактив | stdin в процесс (ввод, Ctrl+C / прерывание); не «только лог команд» |
| **16.4** | Несколько сессий | Вкладки/сплит внутри панели терминала (не корневой nav) |
| **16.5** | Рабочая директория | Показ cwd; смена каталога; опц. привязка к проекту/библиотеке |
| **16.6** | Команды от Mira | По запросу в Диалоге Mira может предложить/выполнить команду **в этой** сессии (с confirm для опасных) |
| **16.7** | История и удобства | История команд сессии; clear; опц. поиск по буферу |
| **16.8** | Настройки терминала | Профиль shell, шрифт/размер — в **Настройки → Общие** или Голос не путать: раздел «Терминал» внутри Настроек |

## Пользовательские сценарии (ориентиры)

1. **Диалог:** «Объясни простыми словами…» → развёрнутый ответ голосом и текстом, с уточняющими вопросами.
2. **Память:** «О чём мы вчера говорили про отпуск?» → Mira находит прошлый разговор и резюмирует.
3. **Сеть:** «Что сейчас погоды в Москве?» → ответ с опорой на интернет.
4. **Экран:** «Что у меня открыто?» / «Нажми на кнопку сохранить» → видит экран и действует.
5. **Браузер:** «Найди сайт с рецептом, который я открывал на прошлой неделе» → история + критерии → открытие.
6. **Мессенджер:** «Напиши Ивану в Telegram, что встречу переносим» / «Ответь ему в WhatsApp, что согласна» → выбор чата и отправка от имени пользователя.
7. **Blender:** «Собери простую сцену с кубом и светом в Blender» → подключаются Blender-skills, Mira работает в Blender end-to-end.
8. **Обучение:** загрузить книгу/лекцию → статус «разбор готов» + план → «используй фразы/логику из этого» в диалоге → при необходимости «создай skill» с подтверждением.
9. **Студия голоса:** «Создать голос» → фразы → загрузка записей → Mira сама обработала → «ещё фразы» при необходимости → голос сильнее/словарный запас шире.
10. **Терминал:** Мастерская → Терминал → интерактивный shell; из Диалога — «выполни в терминале …» с confirm при риске.

## Нефункциональные требования

- Секреты и API-ключи — только `.env`, не в git.
- Контроль экрана, браузера и **исходящие сообщения в мессенджерах** — **только по явной команде** пользователя; перед отправкой — превью и подтверждение (детали в RULES/MEMORY).
- Провайдеры ИИ сменные; продукт не lock-in на одного вендора.
- История разговоров локальна (SQLite); удаление/очистка — обязательный UX позже.
- Человечность речи измеряем на слух при выборе TTS (зафиксировать выбор в MEMORY).
- Аккаунты мессенджеров — сессии/токены пользователя локально; не рассылать без команды и без подтверждения.
- Материалы библиотеки (#14) и выученные фрагменты хранятся локально; автосоздание skill — только с подтверждением (см. 14.7).
- Корпус и модели студии голоса (#15) хранятся локально; генератор фраз обязан дедуплицировать уже созданные/записанные.
- Терминал (#16) выполняется с правами пользователя ОС; разрушительные команды — confirm (как экран/мессенджеры).
- Пока **F12** не реализован, для must действует жёсткий режим: опасные действия и исходящие сообщения — **всегда** превью + confirm (как сейчас в RULES).
- **F10/F11**: секреты не попадают в export-пакет без явной опции; «забыть» необратимо без предварительного backup-предупреждения.

## Критерии готовности (обязательный набор)

Считаем обязательный scope закрытым, когда для пунктов **1–16** статус ≥ `partial` с рабочим happy-path, а для приёмки продукта — `done` по каждому:

1. Свободный диалог через выбранный LLM.  
2. Ответ озвучен «не роботом» (согласованный TTS).  
3. Вопрос про прошлый разговор находит историю.  
4. Запрос с опорой на интернет выполняется.  
5. Можно переключить Claude / Gemini / GPT (или эквивалент).  
6–7. Mira видит экран и выполняет простую UI-команду.  
8. Открытие сайта / поиск по истории браузера по критерию.  
9. Skill добавлен в каталог; в обычном диалоге неактивен; при задаче «напиши код» (или явной команде) подключается нужный skill и учитывается.  
10. Протокол добавлен через md и через Панель; по команде выполняется последовательность шагов.  
11. Можно выбрать голос из списка и добавить новый — озвучка идёт выбранным.  
12. По команде отправлено/отвечено сообщение в ≥1 мессенджере (TG или WhatsApp/Instagram); превью + confirm.  
13. По задаче в Blender выполнен осмысленный объём работы; Blender-skills активны только на время этой задачи.  
14. Загружен материал → выполнен разбор (14.3) и план (14.4) → знания доступны в диалоге (14.6); предложенный skill создаётся только после confirm (14.7).  
15. Цикл студии проходит end-to-end минимум один раз; после загрузки обработка идёт без ручного «запусти анализ/train»; можно сгенерировать вторую пачку фраз с дедупом и обновить TTS; голос в #11.  
16. Встроенный терминал: интерактивный shell, ≥1 сессия, копирование вывода; команда из Диалога может уйти в терминал с confirm при опасности.
