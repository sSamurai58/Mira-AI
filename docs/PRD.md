# PRD

Продукт: локальное приложение денежного потока  
**депозит → счета → доля → вывод**.

Источник правды по scope. Фича без строки здесь — не целевая (см. `RULES.md`).

## Цель

Дать одному пользователю на одной машине прозрачный контур:

1. Внести средства (**депозит**).
2. Разложить по **счетам**.
3. Зафиксировать **долю** (правила распределения / участия).
4. **Вывести** средства с аудируемой историей.

Всё хранится локально (SQLite), без обязательного облака.

## Есть vs заглушки

Легенда статусов:

| Статус | Значение |
|--------|----------|
| `done` | Реализовано и usable |
| `partial` | Есть каркас, поведение неполное |
| `stub` | Заглушка / описание без рабочей логики |
| `planned` | В scope, ещё не начато |
| `out` | Вне текущего scope |

### Документация и репозиторий

| Элемент | Статус | Комментарий |
|---------|--------|-------------|
| Папка `docs/` | `done` | Каркас живых документов |
| `MEMORY` / `RULES` / `PRD` / `DESIGN` / `ARHITECTURE` | `done` | Первичный контент |
| Рабочий код приложения | `planned` | В репо пока только docs |
| Старый TTS (`mira_tts`) | `out` | Удалён; не часть продукта |

| Возможность | Статус | Примечание |
|-------------|--------|------------|
| Создание / просмотр депозита | `stub` | Экран и модель — в DESIGN/ARHITECTURE; логики нет |
| Список счетов и балансы | `stub` | |
| Правила доли (проценты / фиксированные части) | `stub` | |
| Операция вывода | `stub` | |
| История операций (аудит) | `planned` | Нужна с первой рабочей транзакцией |
| Мультивалюта | `out` | Пока одна валюта учёта (TBD в MEMORY) |

### Платформа

| Возможность | Статус | Примечание |
|-------------|--------|------------|
| Один процесс приложения | `planned` | Решение принято — см. MEMORY |

| Тёмный UI + табы | `stub` | Спека в DESIGN |

| Платёжные интеграции | `out` | До явного решения в MEMORY |

## Пользовательский сценарий (целевой)

1. Открыть приложение → таб **Счета** / обзор.
2. Зафиксировать **депозит** (сумма, дата, комментарий).
3. Распределить на счета по правилам **доли** (или вручную).
4. Инициировать **вывод** со счёта; остатки и история обновляются атомарно в SQLite.
5. При ошибке / нехватке средств — отказ без частичного списания.

## Нефункциональные требования

- Локальный запуск без сети (кроме будущих опциональных интеграций).
- Данные переживают перезапуск (файл SQLite).
- Секреты не в git (`.env`).
- Stub-экраны не имитируют успешные деньги без записи в БД.

## Критерии готовности MVP

MVP считается достигнутым, когда:

1. Можно создать депозит, увидеть счета, применить долю, сделать вывод — всё в UI.
2. Каждая операция пишется в SQLite в одной транзакции.
3. После перезапуска балансы совпадают с историей.
4. В PRD статусы этих пунктов = `done`, stubs сняты.
