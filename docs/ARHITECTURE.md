# ARHITECTURE

Устройство системы: один процесс, SQLite, границы модулей, дерево репозитория.  
Имя файла намеренно `ARHITECTURE.md` (см. `RULES.md` / `MEMORY.md`).

## Принципы

1. **Один процесс** — UI и доменная логика в одном приложении; без сети микросервисов.
2. **Один файл данных** — SQLite; путь из окружения (`DATABASE_PATH`).
3. **Чёткие границы** — UI не пишет SQL напрямую; домен не знает про виджеты.
4. **Транзакции** — депозит / перераспределение доли / вывод — атомарно.
5. **Явные stubs** — незавершённые куски помечены и отражены в `PRD.md` / `DESIGN.md`.

## Один процесс

```
┌──────────────────────────────────────────┐
│              App process                 │
│  ┌─────────────┐    ┌─────────────────┐  │
│  │     UI      │───▶│  Domain / App    │  │
│  │  (экраны)   │◀───│  services        │  │
│  └─────────────┘    └────────┬────────┘  │
│                              │           │
│                     ┌────────▼────────┐  │
│                     │  SQLite store   │  │
│                     └─────────────────┘  │
└──────────────────────────────────────────┘
```

- Фоновые задачи (если появятся) — потоки/async **внутри** того же процесса, не отдельные сервисы.
- Нет скрытого второго хранилища «для кэша» без записи в MEMORY.

## SQLite

Целевые сущности (черновик схемы; миграции появятся с кодом):

| Таблица | Назначение |
|--------|------------|
| `accounts` | Счета: id, имя, доля, служебные флаги |
| `operations` | Журнал: депозит / перевод / вывод / корректировка |
| `balances` или derived | Либо таблица остатков, либо расчёт из журнала — выбрать одно в MEMORY при реализации |
| `meta` | Версия схемы, служебные ключи |

Правила:

- Все денежные изменения — в одной DB-транзакции.
- Суммы хранить целочисленно (минорные единицы), не float.
- Файл БД не коммитить; путь через `.env` (см. `RULES.md`).

## Границы модулей

Целевое разбиение (имена пакетов уточнить при выборе стека):

| Слой | Ответственность | Не делает |
|------|-----------------|-----------|
| `ui` | Экраны, табы, токены, ввод | Бизнес-инварианты, SQL |
| `app` / `domain` | Депозит, доля, вывод, валидация | Виджеты, цвета |
| `store` | SQLite, миграции, запросы | Правила продукта сверх персистентности |
| `config` | Чтение `.env`, пути | Секреты в логах |

Зависимости только «вниз»: `ui → domain → store`. Обратных импортов нет.

## Потоки данных (MVP)

1. **Депозит:** UI → `DepositService` → store: insert operation (+ обновить остатки) → UI refresh.
2. **Доля:** UI меняет % → domain проверяет сумму долей → store атомарно обновляет accounts.
3. **Вывод:** UI → domain (хватает ли средств) → store transaction → UI / ошибка.

Ошибка на любом шаге — rollback, пользователю янное сообщение (токен `--danger`).
