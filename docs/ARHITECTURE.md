# ARHITECTURE

Устройство Mira: один процесс, голосовой пайплайн, SQLite, границы модулей, дерево репо.  
Имя файла намеренно `ARHITECTURE.md` (см. `RULES.md` / `MEMORY.md`).

## Принципы

1. **Один процесс** — UI, ASR/TTS-оркестрация и диалог в одном приложении.
2. **Один файл данных** — SQLite; путь из окружения (`DATABASE_PATH`).
3. **Чёткие границы** — UI не вызывает движки ASR/TTS напрямую в обход оркестратора; store не знает виджеты.
4. **Пайплайн голоса** — mic → ASR → dialog/intents → (skills) → TTS → speaker.
5. **Явные stubs** — незавершённое помечено в `PRD.md` / `DESIGN.md`.
6. **Финансы — навык фазы 2** — тот же процесс и SQLite, отдельный domain-модуль.

## Один процесс

```
┌─────────────────────────────────────────────────────┐
│                    App process                      │
│  ┌──────────┐   ┌──────────────┐   ┌─────────────┐  │
│  │    UI    │──▶│  Orchestrator│──▶│ ASR / TTS   │  │
│  │ (states) │◀──│  + Dialog    │◀──│  adapters   │  │
│  └──────────┘   └──────┬───────┘   └─────────────┘  │
│                        │                            │
│               ┌────────▼────────┐                   │
│               │ Skills / domain │  (фаза 2: finance)│
│               └────────┬────────┘                   │
│                        │                            │
│               ┌────────▼────────┐                   │
│               │  SQLite store   │                   │
│               └─────────────────┘                   │
└─────────────────────────────────────────────────────┘
```

- Аудио I/O и инференс — потоки/async **внутри** процесса, не микросервисы.
- Адаптеры ASR/TTS сменные; диалог не зависит от конкретного вендора.

## Голосовой пайплайн (MVP)

1. UI → `listening` → захват PCM/WAV с микрофона.
2. `AsrAdapter.transcribe(audio) → text`.
3. `DialogService.handle(text, session)` → ответ + опциональный skill-call.
4. `TtsAdapter.synthesize(reply) → audio` → playback, UI → `speaking`.
5. Store пишет реплики user/assistant в одной логической операции сессии.

Отмена (`stop`): прервать запись или playback; частичный мусор не коммитить как «успех».

## SQLite

| Таблица | Назначение |
|--------|------------|
| `sessions` | Голосовые/текстовые сессии |
| `utterances` | Реплики: роль, текст, timestamps, статус |
| `memory_facts` | Долгосрочные факты (после MVP) |
| `meta` | Версия схемы |
| `accounts` / `operations` | Финансовый навык (фаза 2) |

Правила:

- Реплики и смена сессии — через store, не из UI SQL.
- Денежные изменения (фаза 2) — атомарно, суммы integer (минорные единицы).
- Файл БД не коммитить; путь через `.env`.

## Границы модулей

| Слой | Ответственность | Не делает |
|------|-----------------|-----------|
| `ui` | Состояния, PTT, transcript, табы | Выбор модели ASR, SQL |
| `orchestrator` | Склейка mic/ASR/dialog/TTS/playback | Виджеты, схема БД |
| `dialog` | Интенты MVP, контекст сессии | Прямой доступ к микрофону |
| `asr` / `tts` | Адаптеры движков | Продуктовые интенты |
| `skills` | Навыки (таймер, finance…) | UI-токены |
| `store` | SQLite, миграции | Правила диалога |
| `config` | `.env`, пути, выбор адаптеров | Секреты в логах |

Зависимости «вниз»: `ui → orchestrator → dialog/skills → store`; адаптеры сбоку от orchestrator.
