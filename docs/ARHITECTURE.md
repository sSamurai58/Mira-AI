# ARHITECTURE

Устройство Mira: один процесс, диалог через LLM, память, экран/браузер, человечная речь, SQLite.  
Имя файла намеренно `ARHITECTURE.md` (см. `RULES.md` / `MEMORY.md`).

## Принципы

1. **Один процесс** — UI, оркестрация, инструменты и речь в одном приложении.
2. **Один файл данных** — SQLite; путь из `DATABASE_PATH`.
3. **Сменные адаптеры** — LLM (Claude / Gemini / GPT…), ASR, TTS без lock-in.
4. **Инструменты по команде** — интернет, экран, браузер вызываются явно из диалога.
5. **Явные stubs** — незавершённое в `PRD.md` / `DESIGN.md`.
6. **Обязательный scope** — возможности 1–16 из `PRD.md` (в т.ч. встроенный терминал).

## Пайплайн (обязательный контур)

1. Ввод: голос (ASR) и/или текст.
2. Подъём памяти: поиск по прошлым разговорам → фрагменты в контекст.
3. **Skills on-demand:** из каталога выбрать и временно подключить только релевантные (по задаче/команде); остальные **не** в контексте.
4. Если фраза — **триггер протокола** → выполнить упорядоченные шаги (команды/действия); иначе обычный диалог.
5. LLM (выбранный провайдер) → ответ + tool-calls при необходимости.
6. Инструменты: интернет / экран / браузер / мессенджеры / Blender / **терминал** (при задаче — + skills on-demand).
7. Ответ пользователю текстом + **человечная** озвучка (TTS).
8. Сохранение реплик и метаданных tool-call в SQLite.

Опасные действия экрана/браузера, **исходящие сообщения** и **разрушительные shell-команды** — через подтверждение (RULES/MEMORY).

## SQLite

| Таблица | Назначение |
|--------|------------|
| `sessions` | Сессии диалога |
| `utterances` | Реплики user/assistant + время |
| `memory_index` | Поиск по истории (FTS или аналог) |
| `library_items` | Загруженные материалы (#14): тип, путь, статус разбора |
| `learned_units` | Выученное: фразы, тезисы, логика, стиль; link на `library_items` |
| `learn_plans` | Планы освоения по материалу (14.4) |
| `providers` / settings | Выбранный LLM/TTS/голос (без секретов) |
| `voices` | Записи каталога голосов (id, путь/провайдер, активный) |
| `voice_projects` | Проекты студии (#15): статус, язык |
| `voice_phrases` | Сгенерированные/записанные фразы; флаги recorded; дедуп |
| `voice_clips` | Аудиоклипы корпуса + связь с фразой |
| `meta` | Версия схемы |

Секреты API — только `.env`, не в БД.

## Границы модулей

| Слой | Ответственность | Не делает |
|------|-----------------|-----------|
| `ui` | Состояния, transcript, подтверждения | Прямые вызовы API вендоров |
| `orchestrator` | Склейка диалога, tool-loop, речь | Схема БД |
| `llm` | Адаптеры Claude / Gemini / GPT… | Автоматизация ОС |
| `asr` / `tts` | Распознавание / человечная озвучка | Продуктовая память |
| `voices` | Каталог голосов: list / select / add (#11) | Хранение API-ключей |
| `voice_studio` | Цикл: create → phrases → upload → **auto** analyze+train → more phrases (#15) | Ручной обязательный запуск каждого шага пайплайна; публикация без QA |
| `memory` | Запись и поиск разговоров | Клики по экрану |
| `tools.web` | Интернет-поиск / fetch | Секреты в логах |
| `tools.screen` | Capture + automation | Обход подтверждений |
| `tools.browser` | Вкладки, история, поиск по критериям | Хранение API-ключей |
| `tools.messaging` | TG / WhatsApp / Instagram…: send, reply, resolve chat | Отправка без команды/confirm |
| `tools.blender` | Доступ к Blender: сцена, ops, скрипты | Работа без on-demand Blender-skills там, где они нужны |
| `terminal` | Встроенный PTY/shell: сессии, I/O, cwd (#16) | Подмена внешним окном ОС как единственным вариантом |
| `skills` | Каталог: add; **activate/deactivate on-demand**; load только активных | Держать все skills всегда в промпте; вызов OS в обход tools |
| `library` | Загрузка материалов, статусы разбора (14.1, 14.9) | Тихое удаление выученного без UI |
| `learn` | Анализ, план, запись `learned_units`, черновик skill (14.2–14.8) | Автопубликация skill без confirm |
| `protocols` | Последовательности шагов; md + Панель CRUD/run | Тихие действия без команды пользователя |
| `store` | SQLite, миграции | Правила диалога |
| `config` | `.env`, выбор провайдеров | Секреты в UI/логах |
