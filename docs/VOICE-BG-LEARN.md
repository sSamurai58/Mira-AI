## Продуктовая формулировка v1

> Пока пользователи говорят с Mira, ответы озвучиваются ElevenLabs. Пары текст–аудио **собираются на клиентах** и **свозятся на машину владельца**, где копятся в корпус и **периодически улучшают локальный unit-stitch pack**. EL остаётся учителем и fallback. Цель — вырастить покрытие «живыми» кусками вашего Voice ID, не заменить EL в один шаг.

## Топология (логика)

```
[Клиент 1..N]                    [Машина владельца — Windows]
чат → текст ответа Mira                 │
     → EL TTS (Voice ID)                │
     → пара (text, audio, meta)  ──sync──►  корпус Voice Studio
                                            idle / порог N
                                            → stitch rebuild
                                            → pack для speak
     ←────────── (опц.) обновлённый pack / политика ──────────
```

**На клиенте:** не крутить тяжёлый train; максимум буфер/очередь отправки пар.  
**У владельца:** диск корпуса, дедуп, QA клипов, batch rebuild stitch, версия pack.  
**Android/прочие:** могут участвовать в **сборе** (если speak идёт через EL); train worker — на машине владельца.
