# Фон: обучение голоса на озвучке ElevenLabs (feasibility)

**Статус:** только размышление / план. **Кода нет.**  
**Дата:** 2026-11-17.  
**Вопрос заказчика:** можно ли, пока пользователи общаются, в фоне учить голос Mira на парах **текст ↔ аудио озвучки ElevenLabs** (ответы Mira)?

## Короткий ответ

**Да, как контур сбора пар и дообучения локального голоса — реалистично.**  
**Нет гарантии**, что локальная модель станет «тем же» ElevenLabs; и есть **юридический/ToS риск**, если цель — клон/замена EL по их аудио.

## Что уже есть в Mira (опора)

| Кусок | Зачем для идеи |
|-------|----------------|
| Speak через ElevenLabs | На каждый ответ уже есть пара текст → байты аудио |
| Disk TTS cache | Кеш WAV по voice+text (сейчас LRU маленький, не «корпус обучения») |
| Voice Studio corpus + train | Уже умеем пары фраза/WAV → pack / neural train / unit-stitch |
| F5 / Chatterbox sidecars | Клон по reference WAV (не online-learn из чата) |
| IVC ElevenLabs | Обратный путь: студия → залить в EL; не «учить локально из EL» |
| Android | Нет native train worker — фон-обучение = **desktop/Windows** |

## Что имеется в виду под «обучается»

Три уровня — разная сложность:

| Уровень | Суть | Реалистичность | Качество vs EL |
|---------|------|----------------|----------------|
| **A. Корпус + unit-stitch** | Копить WAV ответов EL → пополнять lexicon студии → периодический rebuild stitch | **Высокая** | Растёт покрытие «живыми» кусками EL; не полноценный синтез всего |
| **B. Teacher → local neural** | Те же пары → периодический retrain локального neural / sidecar | **Средняя** | Сейчас neural слабее EL; можно дистиллировать тембр/манеру, но не 1:1 |
| **C. Полная замена EL** | Локально звучит как выбранный Voice ID без API | **Низкая / долгая** | Нужны объём, модель, GPU; плюс ToS |

Имеет смысл целиться сначала в **A**, опционально **B**; **C** не обещать.

## Как это могло бы работать (логика, не код)

```
Пользователь ↔ Mira (чат)
        ↓
  Mira отвечает текстом
        ↓
  ElevenLabs TTS (Voice ID)
        ↓
  [фон] сохранить пару (text, audio, voiceId, ts, userId?)
        ↓
  idle / ночь / порог N минут аудио
        ↓
  дописать в Voice Studio corpus → train / stitch rebuild
        ↓
  speak-порядок: сначала свой pack / sidecar, EL — пока учитель или fallback
```

## Плюсы

- Данные «бесплатные» при обычном использовании (учитель уже платится за EL speak).
- Один целевой тембр = ваш Voice ID — корпус согласован.
- Совпадает с текущей архитектурой студии (фразы → корпус → train).
- На Windows (ваш приоритет админки) train worker уже заложен.

## Риски и ограничения

1. **ToS ElevenLabs** — использование их output для обучения **конкурирующей** TTS часто ограничено. Перед реализацией — явно решить: кеш для UX vs train своей модели; при сомнении — юрист / их лицензия. В продукт не зашивать «клон EL» в маркетинг без проверки.
2. **Качество учителя** — MP3/сжатие, артефакты, разный prosody → яд для train. Лучше PCM/высокий bitrate; фильтр коротких/битых клипов.
3. **Объём и диск** — часы диалогов = гигабайты; нужен policy: лимит, дедуп текста, выборочное сохранение.
4. **Когда учить** — не на каждый reply (CPU/вентиляторы); batch на idle; UI «обучается…» / пауза.
5. **Мульти-пользователи (админка)** — один бренд-голос Mira на всех vs голос-per-user: для «вашей» озвучки — **один общий корпус** владельца; чужие ключи не смешивать в чужие голоса.
6. **Катастрофическое забывание** — бесконечный online fine-tune без якоря портит pack; лучше накопил → полная/инкрементальная пересборка с версией.
7. **Приватность** — ответы Mira могут содержать персональные данные пользователей; корпус = чувствительное хранилище (шифрование, TTL, «забыть» из F11).

## Рекомендуемая продуктовая формулировка (когда дойдём до PRD)

> Пока Mira говорит голосом ElevenLabs, пары текст–аудио **можно копить** и **периодически улучшать локальный голос** (stitch / neural). Цель v1 — снизить зависимость от EL на частых фразах и вырастить свой pack; не «мгновенно стать EL».
