# DESIGN

Тёмный UI локального приложения: блоки, токены, табы, экраны, stubs.  
Источник правды по интерфейсу (см. `RULES.md`).

## Направление

- Тема по умолчанию: **тёмная**.
- Один каркас: нижние или боковые **табы** + контент экрана.
- Без «дашборд-каши» на первом экране: один главный смысл на viewport.
- Деньги и статусы — крупная типографика; вторичное — приглушённым текстом.
- Карточки только там, где есть действие или сущность (счёт, операция), не для декора.

## Токены (черновик)

Имена стабильные; конкретные hex можно уточнять в коде, не плодя синонимы.

| Токен | Роль | Старт |
|-------|------|-------|
| `--bg` | Фон приложения | `#0E1116` |
| `--bg-elevated` | Поверхность блока/панели | `#161B22` |
| `--border` | Разделители | `#2A323C` |
| `--text` | Основной текст | `#E8EEF5` |
| `--text-muted` | Вторичный текст | `#8B97A8` |
| `--accent` | CTA / активный таб | `#3DDC97` |
| `--danger` | Ошибки / деструктивное | `#F07178` |
| `--warning` | Предупреждения | `#E6C07B` |
| `--success` | Успех / положительный баланс | `#3DDC97` |
| `--radius` | Скругление контролов | `12px` |
| `--space-1…6` | Ритм отступов | `4 / 8 / 12 / 16 / 24 / 32` |
| `--font-sans` | UI-шрифт | выбрать при фиксации стека (не Inter по умолчанию) |
| `--font-mono` | Суммы, ID операций | tabular figures |

Движение (минимум):

1. Смена таба — короткий crossfade / slide (~150–200 ms).
2. Появление toast / ошибки — fade + лёгкий подъём.
3. Нажатие CTA — press-state без «glow-фейерверков».

## Табы

Корневая навигация (имена можно локализовать в UI, ключи стабильные):

| Ключ | Подпись | Смысл |
|------|---------|-------|
| `overview` | Обзор | Сводка балансов, быстрый вход в депозит/вывод |
| `accounts` | Счета | Список счетов и долей |
| `deposit` | Депозит | Создание депозита / последний депозит |
| `withdraw` | Вывод | Запрос вывода |
| `history` | История | Лента операций |

Правило: не больше одного активного CTA-действия «на деньги» в первом viewport таба.

## Stubs

Пока нет бэкенда:

- Экраны показывают **пустые состояния** или явный `StubBadge`, без фейковых успешных транзакций.
- Нажатие «Подтвердить» на stub: либо no-op с toast «скоро», либо запись только после появления SQLite-слоя.
- В коде и в этой таблице статус `stub` снимается только вместе с обновлением `PRD.md`.

Wireframe (логика, не пиксели):

```

│  BalanceHeader              │
│  …                          │
│  AccountRow / form / list   │
│                             │
├─────────────────────────────┤
│ Обзор  Счета  +  Вывод  …   │
└─────────────────────────────┘
```
