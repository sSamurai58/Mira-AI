# RULES

Договорённости команды и агентов. При конфликте с кодом — сначала правим код или явно фиксируем исключение в `MEMORY.md`.

| Файл | Назначение |
|------|------------|
| [MEMORY.md](./MEMORY.md) | Статус, решения, баги, хронология |
| [RULES.md](./RULES.md) | Договорённости, индекс, стек, политика `.env` |

Новый документ в `docs/` — сразу добавить строку в эту таблицу. `WIP.md` не источник правды: спорные пункты после принятия переносятся сюда/`MEMORY`/`PRD`/`DESIGN`/`ARHITECTURE` и удаляются из WIP.

## Договорённости

1. **Источник правды по продукту** — `PRD.md`. Фичи без строки в PRD не считаются целевыми.
2. **Источник правды по устройству** — `ARHITECTURE.md`. Границы модулей не размывать «для удобства».
3. **Источник правды по UI** — `DESIGN.md`. Новые экраны описывать там до или вместе с реализацией.
4. **Память** — решения и баги пишем в `MEMORY.md`, не в чат и не только в коммит.
5. **Один процесс** — без отдельного микросервисного контура; фон и UI живут в одном приложении.
6. **Данные** — только SQLite (файл БД локально). Нет скрытых внешних БД «на потом».
7. **Заглушки** — явно помечать `stub` в коде и в PRD/DESIGN; не выдавать stub за готовую фичу.
8. **Имя файла архитектуры** — `ARHITECTURE.md` (историческое написание); не переименовывать без записи в MEMORY.
9. **Коммиты** — маленькие, по смыслу; секреты и `.env` не коммитить.
10. **Язык docs** — русский, если нет причины иначе.
11. **WIP** — черновики только в `WIP.md`; после реализации перенос в основные docs и удаление из WIP.
12. **Обязательные возможности** — только список в `PRD.md` (§ must-have); доп. фичи не подменять must.
13. **Экран и браузер** — действия только по явной команде; разрушительное — с подтверждением в UI.

## Стек

| Рантайм | Один локальный процесс | принято |
| Хранилище | SQLite | принято |
| UI | Тёмная тема, состояния голоса, табы из `DESIGN.md` | принято направление |
| Голос | ASR + человечный TTS через адаптеры | принято направление |

| Конфиг/секреты | `.env` (+ пример без секретов) | принято |

Пока язык/фреймворк не зафиксированы — не плодить параллельные прототипы без записи решения.

## Политика `.env`

- Файл `.env` — **только локально**, в `.gitignore`.
- В репозитории держать `.env.example` с ключами и пустыми/фиктивными значениями, без реальных секретов.
- В коде читать секреты только из окружения / `.env`-загрузчика; не хардкодить токены, пароли, ключи API.
- Не логировать значения секретов.
- Не копировать `.env` в `docs/`, скриншоты, issue, PR.
- Если секрет утёк — ротация + запись в `MEMORY.md` (баг/инцидент).

Минимальный набор ключей (расширять по мере появления интеграций):

```env
# .env.example
APP_ENV=development
DATABASE_PATH=./data/app.sqlite
# LLM (заполнять локально, не коммитить)
# OPENAI_API_KEY=
# ANTHROPIC_API_KEY=
# GOOGLE_API_KEY=
```
