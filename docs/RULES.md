## Договорённости

1. **Источник правды по продукту** — `PRD.md`. Фичи без строки в PRD не считаются целевыми.
2. **Источник правды по устройству** — `ARHITECTURE.md`. Границы модулей не размывать «для удобства».
3. **Источник правды по UI** — `DESIGN.md` (IA: 4 корневых пункта, карта Настроек). Новые экраны — сначала «куда класть», не новый корневой таб.
4. **Память** — решения и баги пишем в `MEMORY.md`, не в чат и не только в коммит.
5. **Один процесс** — без отдельного микросервисного контура; фон и UI живут в одном приложении.
6. **Данные** — только SQLite (файл БД локально). Нет скрытых внешних БД «на потом».
7. **Заглушки** — явно помечать `stub` в коде и в PRD/DESIGN; не выдавать stub за готовую фичу.
8. **Имя файла архитектуры** — `ARHITECTURE.md` (историческое написание); не переименовывать без записи в MEMORY.
9. **Коммиты** — маленькие, по смыслу; секреты и `.env` не коммитить.
10. **Язык docs** — русский, если нет причины иначе.
11. **WIP** — черновики только в `WIP.md`; после реализации перенос в основные docs и удаление из WIP.
12. **Обязательные возможности** — только список в `PRD.md` (§ must-have); блок «на будущее» (`F…`) не подменяет must и не тянется в код раньше стабилизации 1–16.
13. **Экран, браузер, мессенджеры** — действия только по явной команде; разрушительное и **отправка сообщений** — с превью и подтверждением в UI. Пока PRD **F12** не реализован, режим confirm = **`always`**. После F12 допустимы `smart` / `dangerous-list` только через **Настройки → Общие**.
14. **Skills** — установленные ≠ активные; в контекст попадают только подключённые по задаче/команде; не грузить весь каталог «на всякий случай».
15. **Обучение по материалам (#14)** — skill из разбора только после confirm пользователя; выученное хранить со ссылкой на источник.
16. **Студия голоса (#15)** — генератор фраз не повторяет уже созданные/записанные; после загрузки записей анализ и сборка TTS **автоматически**; в каталог (#11) только после успешной обработки; цикл «ещё фраз» — норма развития голоса.
17. **UX IA** — на главной только диалог; API/ключи/интеграции только в Настройках; Мастерская — хаб skills/протоколы/голоса/библиотека/**терминал**; **не плодить корневые табы** под каждую PRD-фичу (см. `DESIGN.md`).
18. **Терминал (#16)** — встроенный PTY в Мастерской (опц. split из Диалога); опасные команды — confirm; prefs shell/шрифт — в Настройках.
19. **Agent skills (дизайн/анимация)** — при работе над UI, motion, polish Mira читать on-demand скиллы из `.cursor/skills/` (источник: [emilkowalski/skills](https://github.com/emilkowalski/skills)); **не** путать с продуктовыми skills PRD #9; не грузить все сразу.
20. **Профили / backup (F10/F11)** — ключи API не коммитить и не класть в export без явной опции пользователя; «забыть» — только с confirm и предупреждением про необратимость.
21. **Doctor (F13)** — пользовательские сообщения об ошибках: причина простым языком + следующий шаг; сырые логи — в панели Doctor, не спамом на Home.

## Политика `.env`

- Файл `.env` — **только локально**, в `.gitignore`.
- В репозитории держать `.env.example` с ключами и пустыми/фиктивными значениями, без реальных секретов.
- В коде читать секреты только из окружения / `.env`-загрузчика; не хардкодить токены, пароли, ключи API.
- Не логировать значения секретов.
- Не копировать `.env` в `docs/`, скриншоты, issue, PR.
- Если секрет утёк — ротация + запись в `MEMORY.md` (баг/инцидент).

Минимальный набор ключей (расширять по мере появления интеграций):

```env
# .env.example
APP_ENV=development
DATABASE_PATH=./mira/database/mira.db
# LLM (заполнять локально, не коммитить)
# OPENAI_API_KEY=
# ANTHROPIC_API_KEY=
# GOOGLE_API_KEY=
```
