# Команда продукта

Пакет Cursor Skills для сборки одного продукта через роли: менеджер, продакт, дизайнер, фронтенд, бэкенд, тестировщик, DevOps и при необходимости специалист предмета, мобильный, macOS или Linux.

Пользователь говорит с **менеджером**. Менеджер пишет одно поручение одной роли, принимает сдачу и ведёт папку `docs/` в репозитории продукта.

## Быстрый старт

1. Подключите эту папку как skill / agent context в Cursor (корень пакета — [`SKILL.md`](SKILL.md)).
2. Дайте указание команде обычным языком: «собери выпуск», «скажи дизайнеру», «проверь перед выкладкой».
3. Менеджер создаст или дополнит `docs/` в корне продукта и отправит первую роль.

Точка входа для агента: [`SKILL.md`](SKILL.md). Правила поведения агента: [`AGENTS.md`](AGENTS.md).

## Роли

| Роль | Файл | Что сдаёт |
|---|---|---|
| Менеджер | [`manager/SKILL.md`](manager/SKILL.md) | Поручение, актуальные `docs/`, короткий отчёт пользователю |
| Продакт | [`product/SKILL.md`](product/SKILL.md) | Одностраничное решение выпуска |
| Дизайнер | [`designer/SKILL.md`](designer/SKILL.md) | Спецификация экранов, состояний, токенов и текстов |
| Бэкенд | [`backend/SKILL.md`](backend/SKILL.md) | Контракт: сущности, операции, ошибки, права |
| Фронтенд | [`frontend/SKILL.md`](frontend/SKILL.md) | Работающий клиент по спецификации и контракту |
| Специалист предмета | [`domain/SKILL.md`](domain/SKILL.md) | Правила области, запреты, словарь |
| Мобильный | [`mobile/SKILL.md`](mobile/SKILL.md) | Сборка телефона по тем же экранам и контракту |
| macOS | [`macos/SKILL.md`](macos/SKILL.md) | Приложение Mac |
| Linux | [`linux/SKILL.md`](linux/SKILL.md) | Приложение Linux |
| Тестировщик | [`tester/SKILL.md`](tester/SKILL.md) | Полный отчёт находок и вердикт выкладки |
| DevOps | [`devops/SKILL.md`](devops/SKILL.md) | CI, окружения, выкладка, откат, секреты |

Второй бэкенд заводят по тому же [`backend/SKILL.md`](backend/SKILL.md) с именным куском системы (оплата, очередь, поиск). Два бэкенда без границы куска не создают.

## Порядок сдачи

1. Менеджер создаёт и ведёт `docs/`, пишет поручение.
2. Продакт — решение: человек, работа, этот выпуск, снаружи, проверки.
3. Дизайнер — экраны и состояния с именами продакта.
4. Бэкенд — контракт данных и операций.
5. Фронтенд — сборка на контракте по спецификации.
6. Специалист предмета — если в области дорогая ошибка.
7. Мобильный / macOS / Linux — если поверхность входит в выпуск.
8. DevOps — пайплайн и выкладка, когда выпуск идёт к релизу.
9. Тестировщик — проход, секьюрити, релиз-чеклист; вердикт менеджеру.

Без артефакта предыдущей роли следующий ход не стартует. Продакта не подменяют дизайном, дизайнера — вёрсткой.

## Документы проекта (`docs/`)

Менеджер держит десять файлов в корне продукта:

| Файл | Назначение |
|---|---|
| `PRD.md` | Требования и путь выпуска |
| `ARCHITECTURE.md` | Стек, схема, структура |
| `RULES.md` | Правила разработки |
| `DESIGN.md` | Дизайн-система и токены |
| `TASKS.md` | Задачи и этапы |
| `MEMORY.md` | Статус, решения, баги, изменения |
| `DECISIONS.md` | ADR |
| `GLOSSARY.md` | Единые имена экранов, сущностей, ошибок |
| `RELEASE.md` | Чеклист выкладки |
| `RISKS.md` | Риски и блокеры |

Выкладка в production ждёт вердикта тестировщика `к выкладке` и заполненного `docs/RELEASE.md`.

Внутри роли дизайнера лежат отдельные craft-скиллы. Их открывают по задаче хода, но сдача менеджеру идёт по шаблону [`designer/SKILL.md`](designer/SKILL.md):

## Общие правила

- Один ход — одна роль — один артефакт.
- Имена экранов, сущностей и ошибок совпадают у всех ролей и живут в `docs/GLOSSARY.md`. Новое имя вводит продакт.
- Спор о вкусе закрывает дизайнер; о правиле данных — бэкенд; о правде области — специалист предмета; долгий спор о стеке — ADR в `docs/DECISIONS.md`.
- Описание без проходимого пути не считается сдачей фронтенда, мобильного, macOS и Linux.
- Отчёт тестировщика уходит менеджеру целиком, без отбора находок.
- Язык ответа совпадает с языком пользователя. Имена в коде — как в контракте.
