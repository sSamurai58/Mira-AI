Поток Extract
Найдите повторяемые паттерны, компоненты и design tokens, затем извлеките и объедините их в design system для системного повторного использования.
Шаг 1: Обнаружьте Design System
Найдите design system, библиотеку компонентов или общую UI-директорию. Поймите её структуру: организацию компонентов, соглашения об именовании, структуру design tokens, соглашения import/export.
КРИТИЧНО: Если design system не существует, ОСТАНОВИТЕСЬ и используйте структурированный инструмент вопросов Codex, когда он доступен; если недоступен, спросите напрямую в чате, чтобы уточнить то, что нельзя вывести. — прежде чем создавать систему. Сначала поймите предпочтительное расположение и структуру.
Шаг 2: Найдите паттерны
Ищите возможности извлечения в целевой области:
Повторяющиеся компоненты: похожие UI-паттерны, используемые 3+ раза (buttons, cards, inputs)
Жёстко заданные значения: цвета, отступы, типографика, тени, которые должны стать tokens
Несогласованные вариации: несколько реализаций одной и той же концепции
Паттерны композиции: повторяющиеся layout- или interaction-паттерны (form rows, toolbar groups, empty states)
Стили текста: повторяющиеся комбинации font-size + weight + line-height
Паттерны анимации: повторяющиеся комбинации easing, duration или keyframe
Оцените ценность: извлекайте только то, что используется 3+ раза с одним и тем же намерением. Преждевременная абстракция хуже дублирования.
Шаг 3: Спланируйте извлечение
Создайте системный план:
Компоненты для извлечения: какие UI-элементы станут переиспользуемыми компонентами?
Tokens для создания: какие жёстко заданные значения станут design tokens?
Варианты для поддержки: какие вариации нужны каждому компоненту?
Соглашения об именовании: имена компонентов, tokens, props, совпадающие с существующими паттернами
Путь миграции: как рефакторить существующие использования под новые общие версии
ВАЖНО: Design systems растут инкрементально. Извлекайте то, что явно переиспользуемо сейчас, а не всё, что когда-нибудь может стать переиспользуемым.
Шаг 4: Извлеките и обогатите
Создайте улучшенные переиспользуемые версии:
Компоненты: понятный props API с разумными defaults, корректные варианты для разных use cases, встроенная accessibility (ARIA, keyboard navigation, focus management), документация и примеры использования
Design tokens: ясное именование (primitive vs semantic), правильная иерархия и организация, документация когда использовать каждый token
Паттерны: когда использовать этот паттерн, примеры кода, вариации и комбинации
Шаг 5: Мигрируйте
Замените существующие использования новыми общими версиями:
Найдите все экземпляры: найдите паттерны, которые вы извлекли
Заменяйте системно: обновите каждое использование на общую версию
Тщательно тестируйте: обеспечьте визуальный и функциональный паритет
Удалите мёртвый код: уберите старые реализации
Шаг 6: Задокументируйте
Обновите документацию design system:
Добавьте новые компоненты в библиотеку компонентов
Задокументируйте использование tokens и значения
Добавьте примеры и гайдлайны
Обновите Storybook или каталог компонентов
НИКОГДА:
Не извлекайте разовые, контекстно-специфичные реализации без обобщения
Не создавайте компоненты настолько общие, что они бесполезны
Не извлекайте без учёта существующих соглашений design system
Не пропускайте корректные TypeScript types или документацию props
Не создавайте tokens для каждого отдельного значения (tokens должны иметь семантический смысл)
Не извлекайте вещи с разным намерением (две кнопки, которые выглядят похоже, но служат разным целям, должны остаться раздельными)
