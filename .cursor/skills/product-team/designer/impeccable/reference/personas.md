# Тестирование дизайна по персонам

Тестируйте интерфейс глазами 5 разных пользовательских архетипов. Каждая персона раскрывает разные failure modes, которые упускает единый взгляд «design director».

**Как использовать**: выберите 2–3 персоны, наиболее релевантные критикуемому интерфейсу. Пройдите основной user action от лица каждой. Сообщайте конкретные red flags, а не общие опасения.

---

## 1. Нетерпеливый power user: «Alex»


**Profile**: эксперт в похожих продуктах. Ждёт эффективности, ненавидит hand-holding. Найдёт shortcuts или уйдёт.

**Behaviors**:
- Пропускает весь онбординг и инструкции
- Сразу ищет keyboard shortcuts
- Пытается bulk-select, batch-edit и автоматизировать
- Раздражается обязательными шагами, которые кажутся лишними
- Уходит, если что-то ощущается медленным или покровительственным

**Test Questions**:
- Может ли Alex завершить основную задачу менее чем за 60 секунд?
- Есть ли keyboard shortcuts для частых действий?
- Можно ли полностью пропустить онбординг?
- Есть ли у модалок keyboard dismiss (Esc)?
- Есть ли «power user» path (shortcuts, bulk actions)?

**Red Flags** (сообщайте конкретно):
- Принудительные туториалы или непропускаемый онбординг
- Нет keyboard navigation для основных действий
- Медленные анимации, которые нельзя пропустить
- Workflow «по одному элементу», где batch был бы естественен
- Лишние confirmation steps для низкорисковых действий

---

## 2. Растерянный новичок: «Jordan»

**Profile**: никогда не пользовался продуктами такого типа. Нуждается в guidance на каждом шаге. Скорее уйдёт, чем разберётся.

**Behaviors**:
- Внимательно читает все инструкции
- Колеблется перед кликом по незнакомому
- Постоянно ищет помощь или поддержку
- Неверно понимает jargon и аббревиатуры
- Берёт самую буквальную интерпретацию любой подписи

**Test Questions**:
- Очевидно ли первое действие за 5 секунд?
- Все ли иконки подписаны текстом?
- Есть ли контекстная помощь в точках решения?
- Терминология предполагает предварительные знания?
- Есть ли понятный «back» или «undo» на каждом шаге?

**Red Flags** (сообщайте конкретно):
- Навигация только иконками без подписей
- Технический jargon без объяснения
- Нет видимой опции помощи или guidance
- Неясные следующие шаги после завершения действия
- Нет подтверждения, что действие удалось

---

## 3. Пользователь, зависящий от доступности: «Sam»

**Profile**: использует screen reader (VoiceOver/NVDA), только keyboard navigation. Может иметь low vision, motor impairment или cognitive differences.

**Behaviors**:
- Табает по интерфейсу линейно
- Опирается на ARIA labels и структуру заголовков
- Не видит hover-состояний и visual-only индикаторов
- Нужен достаточный color contrast (минимум 4.5:1)
- Может использовать browser zoom до 200%

**Test Questions**:
- Можно ли пройти весь primary flow только с клавиатуры?
- Все ли interactive elements focusable с видимыми focus indicators?
- Есть ли у изображений осмысленный alt text?
- Соответствует ли color contrast WCAG AA (4.5:1 для текста)?
- Объявляет ли screen reader смены состояний (loading, success, errors)?

**Red Flags** (сообщайте конкретно):
- Взаимодействия только кликом без keyboard-альтернативы
- Отсутствующие или невидимые focus indicators
- Смысл передаётся только цветом (red = error, green = success)
- Неподписанные form fields или buttons
- Time-limited действия без возможности продления
- Кастомные компоненты, ломающие поток screen reader

---

## 4. Намеренный stress-тестер: «Riley»

**Profile**: методичный пользователь, который выводит интерфейсы за happy path. Проверяет edge cases, вводит неожиданные данные и ищет пробелы в опыте.

**Behaviors**:
- Намеренно тестирует edge cases (empty states, длинные строки, спецсимволы)
- Отправляет формы с неожиданными данными (emoji, RTL-текст, очень длинные значения)
- Пытается сломать workflows: назад, refresh mid-flow, открытие в нескольких вкладках
- Ищет несоответствия между обещаниями UI и реальным поведением
- Методично документирует проблемы

**Test Questions**:
- Что происходит на краях (0 items, 1000 items, очень длинный текст)?
- Восстанавливаются ли error states изящно или UI остаётся сломанным?
- Что при refresh mid-workflow? Сохраняется ли state?
- Есть ли функции, которые «работают», но дают сломанный результат?
- Как UI обрабатывает неожиданный ввод (emoji, спецсимволы, paste из Excel)?

**Red Flags** (сообщайте конкретно):
- Функции, которые «работают», но тихо падают или дают неверный результат
- Обработка ошибок, раскрывающая технические детали или оставляющая UI сломанным
- Empty states без пользы («No results» без guidance)
- Workflows, теряющие данные пользователя при refresh или навигации
- Несогласованное поведение похожих взаимодействий в разных частях UI

---

## 5. Отвлечённый mobile-пользователь: «Casey»

**Profile**: пользуется телефоном одной рукой на ходу. Часто прерывается. Возможно, на медленном соединении.

**Behaviors**:
- Только большим пальцем; предпочитает действия внизу экрана
- Прерывается mid-flow и возвращается позже
- Часто переключается между приложениями
- Ограниченное внимание и низкое терпение
- Печатает как можно меньше, предпочитает taps и selections

**Test Questions**:
- Основные действия в thumb zone (нижняя половина экрана)?
- Сохраняется ли state, если пользователь ушёл и вернулся?
- Работает ли на медленных соединениях (3G)?
- Используют ли формы autocomplete и smart defaults?
- Touch targets минимум 44×44pt?

**Red Flags** (сообщайте конкретно):
- Важные действия вверху экрана (недоступны большим пальцем)
- Нет persistence state; прогресс теряется при смене вкладки или прерывании
- Требуется большой текстовый ввод там, где сработала бы selection
- Тяжёлые assets грузятся на каждой странице (нет lazy loading)
- Крошечные tap targets или targets слишком близко друг к другу

## Персоны конкретного проекта

Если в `AGENTS.md` есть секция `## Design Context` (созданная `impeccable teach`), выведите 1–2 дополнительные персоны из данных об аудитории и бренде:

1. Прочитайте описание целевой аудитории
2. Определите основной пользовательский архетип, не покрытый 5 предопределёнными персонами
3. Создайте персону по этому шаблону:

```
### [Role]: "[Name]"

**Profile**: [2-3 key characteristics derived from Design Context]

**Behaviors**: [3-4 specific behaviors based on the described audience]

**Red Flags**: [3-4 things that would alienate this specific user type]
```

Генерируйте project-specific персоны только когда есть реальные данные Design Context. Не выдумывайте детали аудитории; используйте 5 предопределённых персон, если контекста нет.
